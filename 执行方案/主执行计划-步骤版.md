# 主执行计划 · 步骤制（Stage-Gate）

> **本文件是唯一执行源（living document）。**
> 不按固定天数推进，而按「步骤 + 晋级标准」推进。每步有：前置条件(entry) / 任务清单 / 晋级标准(exit) / 调整信号。
> 「参考时长」仅供估算节奏，**不锁死**；任何时刻可根据 JD 词频、市场变化、个人状态调整。
> `执行方案/` 下其余三份（千问/gpt6/workbuddy）为 AI 参考版本，供对照取长，**不直接执行**。

---

## 0. 为什么改成步骤制

| 天数制的问题 | 步骤制的解法 |
|---|---|
| Day 8 必须进 Phase1，哪怕 RAG 还没跑通 | 达到晋级标准才进下一步，没达到就留在本步补 |
| 某天被打断，整个表错位 | 步骤不绑定日期，中断后从当前步骤继续 |
| 新 JD 情报来了没法插 | 新任务插入当前步骤清单，不破坏结构 |
| 已会的技能还要"学完" | 已掌握直接勾掉，跳过 |

**核心原则：用"晋级标准"代替"截止日期"作为推进依据。**

## 1. 四条常驻主线（不随步骤切换，始终推进）

| 主线 | 节奏 | 说明 |
|---|---|---|
| 学习线 | 每周 10-15h | 技术输入，随当前步骤主题变化 |
| 项目线 | 每周 8-12h | 把学的变成 GitHub 作品 |
| 内容线 | **每周 ≥4 条，永远在** | 小红书3+B站1，不受步骤影响 |
| 求职/商业线 | Step2 起加重 | Step0-1 做准备，Step2 试水，Step3-4 收割 |

> 内容线是唯一"无条件常驻"的线——转型过程本身就是产品，停更=停产品。

## 2. 步骤总览

| Step | 名称 | 参考时长 | 晋级门槛（一句话） |
|---|---|---|---|
| Step 0 | 基线与定位 | ~1 周 | 有JD词频表+定位已定+第1条已发+环境就绪 |
| Step 1 | 技术地基 + 项目1(RAG) | ~5-6 周 | 项目1上线且能讲清RAG全链路 |
| Step 2 | Agent工程 + 项目2(多Agent) | ~6-7 周 | 项目2上线+试水投递≥30+面试≥2 |

| Step 4 | 上岸 + 产品化 + 变现 | ~6 周 | 入职+产品可售+付费≥15+完成复盘 |

## 3. 各步骤详情

### Step 0 · 基线与定位
- **前置条件**：无（起点）
- **参考时长**：~1 周
- **任务清单**
  - [x] 真实工作经历盘点（Java/DB/中间件/系统设计/业务成果，标注可公开项）
  - [x] 收集 15 条 JD，做词频统计 + 必须/加分/工作内容三分类
  - [ ] 敲定 IP 定位名 + 公众号/小红书/B站统一 ID
  - [ ] 注册并装修 4 平台账号 + GitHub
  - [ ] 发布第 1 条内容（公开承诺型）
  - [ ] 开发环境就绪（IDEA/PyCharm/Docker/Git/API key）
  - [ ] 确认本主执行计划为唯一执行源
- **晋级标准（exit）**
  - 手上有 ≥15 条 JD 的词频表 + 三分类
  - IP 定位名已定，第 1 条内容已发布
  - 4 平台 + GitHub 账号就绪
  - 开发环境可跑通一个 hello-world LLM 调用
- **调整信号**
  - 若 JD 词频显示某技能频次远超预期 → 提升其在 Step1 的优先级
  - 若第 1 条内容 0 互动 → 回改钩子/选题，不进入 Step1 前先修内容

### Step 1 · 技术地基 + 项目1（RAG 知识库）
- **前置条件**：Step 0 exit 全满足
- **参考时长**：~5-6 周
- **学习重点（按 JD 词频排序）**：Python+FastAPI(补门槛) → RAG → Tool Calling → 向量库 → LangChain/LangGraph 其一
- **任务清单**
  - [ ] Python 工程化 + FastAPI 补强（若已会则跳过）
  - [ ] LLM API / Prompt / Function Calling
  - [ ] RAG 全链路：切分→向量化→检索→Rerank→生成
  - [ ] 项目1：程序员面试知识库 RAG 问答系统（Spring Boot + LangChain4j + PGVector）
  - [ ] 项目1 部署上线 + README + 演示视频
- **晋级标准（exit）**
  - 项目1 上线，GitHub 有完整 README + 演示
  - 能脱稿讲清 RAG 全链路 + 3 个优化点
  - 内容累计 ≥20 条
  - 简历 v1 完成（含项目1）
- **调整信号**
  - 项目1 卡壳 >1 周 → 砍功能做最小可用版，先晋级再迭代
  - 黑马课占用 >20% → 立即降速（它是素材不是主线）

### Step 2 · Agent 工程 + 项目2（多Agent 求职助手）
- **前置条件**：Step 1 exit 全满足
- **参考时长**：~6-7 周
- **学习重点**：Agent(ReAct/ToolUse/规划) → 多Agent编排(LangGraph/LangChain4j) → MCP → AI工程化(部署/评估/成本)
- **任务清单**
  - [ ] Agent 基础 + 编排框架
  - [ ] MCP 协议 + Tool 生态
  - [ ] 项目2：多Agent求职助手（简历分析+JD匹配+面试题生成）
  - [ ] 项目2 加评估机制 + 部署
  - [ ] **试水投递 ≥30 份**（练手岗），争取面试 ≥2 场
  - [ ] 简历 v3 定稿
- **晋级标准（exit）**
  - 项目2 上线，含评估机制
  - 投递 ≥30，面试 ≥2，有真实反馈
  - 内容累计 ≥50 条
  - 项目3 需求文档完成
- **调整信号**
  - 到本步中段还没投递 → 立即开始投，别等"学完"
  - 面试通过率 <10% → 回炉简历/项目讲述，必要时回退 Step1 补项目深度

### Step 3 · 求职冲刺 + 项目3（AI 模拟面试官 MVP）
- **前置条件**：Step 2 exit 全满足
- **参考时长**：~6 周
- **任务清单**
  - [ ] 海投 ≥120 份（BOSS主+猎聘+拉勾+内推），面 ≥20 场
  - [ ] 项目3 MVP：文字版→打分反馈→语音版(ASR+TTS)
  - [ ] 项目3 找 3-5 个种子用户测试
  - [ ] 上线人工服务变现：简历优化(¥199) + 模拟面试(¥299)
  - [ ] 谈薪准备 + Offer 对比
- **晋级标准（exit）**
  - 拿到 ≥2 Offer（或 ≥2 终面）
  - 项目3 MVP 上线且有种子用户反馈
  - 付费用户 ≥3
  - 内容累计 ≥85 条
- **调整信号**
  - 投递量不足 → 加量（求职是概率游戏）
  - 项目3 拖垮求职 → **求职优先**，项目3 降级为纯人工服务先验证
  - 一直面不过 → 用面试真题反推 gap，回退补

### Step 4 · 上岸 + 产品化 + 变现
- **前置条件**：Step 3 exit 全满足（至少拿到 Offer）
- **参考时长**：~6 周
- **任务清单**
  - [ ] 谈薪 + 选定 Offer + 入职
  - [ ] 项目3 产品化：支付 + 用户系统 + 落地页
  - [ ] 私域搭建（企微 + 社群）
  - [ ] 4 层产品阶梯上线 ≥3 层
  - [ ] B 端探索（卖给猎头/HR外包）
  - [ ] 180 天大复盘 + 下一份计划
- **晋级标准（exit）**
  - 已入职 / 谈定满意 Offer
  - 产品可售卖（有支付+用户系统）
  - 付费用户 ≥15，副业累计 ≥¥10000
  - 完成大复盘
- **调整信号**
  - 入职后精力崩 → 副业降速到每周 ≤10h，保试用期
  - 产品没人买 → 回退纯人工服务，先赚钱再产品化

## 4. 调整协议（如何"时刻调整"）

每周日做一次 review，只回答 4 个问题：
1. **当前步骤的 exit 完成度多少？**（0-100%）
2. **继续 / 加速 / 回退 / 插入？**
   - 继续：exit <100%，正常推进
   - 加速：某任务已掌握 → 勾掉跳过，提前晋级
   - 回退：exit 连续 2 周无进展 → 回退上一步补基础
   - 插入：新 JD 情报/新工具 → 加入**当前步骤**任务清单，不新建步骤
3. **四条主线是否都在推进？**（内容线必须 ≥4 条/周）
4. **有无红线触碰？**（不虚构/不灰产）

> 步骤之间**允许并行**：内容线永远并行；求职线从 Step2 起并行；商业验证（人工服务）可从 Step3 提前到 Step2 末试水。

## 6. 红线 & 不要做（精简）

- 不虚构薪资/Offer/经历/案例/数据；不代考代面；不承诺保证Offer
- 不从头啃 ML/DL 数学；不为学完黑马而学；不同时运营4平台
- 不在 Step1-2 死磕开发求职工具；不憋大招（先上线再迭代）
- 不等"准备好"才投简历
